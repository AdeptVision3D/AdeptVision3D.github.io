# Decard Studio — инструкции для Claude

Внутренняя «своя Битрикс» студии 3D-визуализации: проекты/кадры, мини-CRM, календарь, отпуска, аналитика, маркетинг. GitHub Pages + Supabase. Владелец проекта — 3D-художник, не программист: объяснять просто, по-русски, по шагам.

## Как работать с кодом (экономия токенов)
- Сначала открыть `docs/CODE-MAP.md`: там у каждой страницы список функций с номерами строк и таблицы. Читать файлы `Read` с `offset/limit`, не целиком.
- Страница = `X.html` (разметка) + `css/X.css` + `js/X.js`. Общее в корне: `common.js`, `icons.js`, `reminders.js`, `styles.css`, `glass.css`, `glass.js`, `glass-fx.js`.
- После правки файла поднять `?v=` в `<link>/<script>` во всех страницах (`Get-ChildItem *.html`), иначе браузеры покажут старое. После крупных правок обновить карту: `scripts/make-code-map.ps1`.
- Скриншоты браузера брать уменьшенными (`scale`), там где хватает — проверять текстом/данными.
- Широкие поиски по проекту — через `Grep`, не через чтение файлов.

## Правила
- Ничего не пушить в GitHub и не публиковать без явного «публикуем/выкатывай». Перед публикацией ставить тег отката `backup-before-...`. Работать в отдельной ветке, в `main` — только fast-forward после подтверждения.
- Сборка Pages иногда не стартует сама: после push проверить `actions/runs?event=dynamic` и при необходимости отправить пустой коммит.
- SQL для Supabase пользователь выполняет сам (SQL Editor); я пишу миграцию в `supabase/migrations/` и даю текст в чат.
- Пароли, PIN и ключи не просить и не вводить. Вход в браузере делает пользователь.
- Тестовые данные в базе помечать «ТЕСТ» и удалять после проверки.
- После публикации заметных изменений — черновик «Что нового» в «Новости» (таблица `company_news`), выкладывать после «да» пользователя.
- Коммиты оканчивать строкой `Co-Authored-By: Claude Sonnet 5.5 <noreply@anthropic.com>`.
